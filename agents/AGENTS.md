## テスト

- テストを書く前に、そのテストが何を守るのか (どの振る舞いか、どの不具合の再発か) を
  一文で言えるようにする。言えないテストは書かない。守るものはテスト名かコメントに残す。
- テストはシンプルに保つ。1 つのテストで確かめる振る舞いは 1 つにし、凝ったヘルパーや
  抽象化より、読んで分かる直書きを選ぶ。
- 無駄なテストを書かない。網羅率のためだけのテストや、言語・ライブラリ・フレームワークが
  保証していることを確かめ直すテストは書かない。
- 重複するテストを書かない。既存のテストが守っている振る舞いを、別の層や似た入力で
  確かめ直さない。足す前に既存のテストを確認する。
- 設定値・定数・ファイルの中身をそのまま確かめるだけのテストを書かない。確かめるなら、
  その設定が効いた結果の振る舞いを確かめる。
- テストの実行時間は可能な限り短くする。sleep、実際のネットワーク、大きな fixture、
  不要なプロセスの起動を避ける。どうしても遅いテストが要るなら、理由を書いて分ける。
- 実装の内部 (private な関数や呼び出し回数) に結び付けず、外から見える振る舞いを確かめる。

## herdr-tasks

- `herdr-tasks` スキルを使用している際は、特に指示がない場合、coodinatorは`pi`、worker は `pi` を
  モデル `openai/gpt-6.2-sol` で起動すること
  (`herdr agent start <name> --kind pi --pane <pane-id> -- --model openai/gpt-6.2-sol`)。
- `herdr-tasks` の worktree 作成には `git worktree add` の代わりに
  `~/bin/herdr-task-worktree --repo <repo> --path <task-dir>/worktrees/<branch> --branch <branch> --base <base-sha>`
  を使う。tab はスキルの手順どおり別途作成する。
- その worktree を消すときは `git worktree remove` の代わりに
  `~/bin/herdr-task-worktree remove --path <task-dir>/worktrees/<branch>` を使う。
  マージ済みのブランチも消すなら `--delete-branch` を付ける。未コミットの変更や
  未追跡のファイルがあると拒否されるので、その場合は消してよいかユーザーに確認する。
- worktree を作る前などに元リポジトリを fetch するときは、`git -C <repo> fetch` の代わりに
  `~/bin/herdr-task-worktree fetch --repo <repo>` を使う (origin を fetch する)。
  サンドボックスが有効だと、起動ディレクトリの外のリポジトリには書き込めないため。
- herdr の許可対象操作は、シェル変数を展開済みの単独コマンドで実行する。
  複合コマンドや変数展開は自動許可ルールに含めない。自動許可のために
  指示の意味や安全確認を変えたり、拒否された操作を別表記で回避したりしない。
